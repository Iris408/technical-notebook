2026-08-21 · PartsPilot v2 · フロントエンド / React / JavaScript / FastAPI / デバッグ / フルスタック

APIレスポンスの形が原因のReact表示エラーを修正する

parts配列ではなく、APIレスポンスのラッパーオブジェクトをstateに保存していたことによるReactの表示エラーを修正しました。

詳細を見る詳細を閉じる：APIレスポンスの形が原因のReact表示エラーを修正する

問題: PartsPilotのフロントエンドはバックエンドからデータを受け取れていましたが、parts.map() を実行しようとしたところで画面がエラーになりました。Reactは parts が配列であることを前提にしていましたが、stateにはレスポンスオブジェクト全体が入っていました。

原因: FastAPIのエンドポイントは配列を直接返すのではなく、items プロパティを持つオブジェクトを返していました。フロントエンドでは setParts(data) を使っていたため、そのラッパーオブジェクトがstateに保存されていました。map などの配列メソッドは、このオブジェクトには使えません。

修正: 返されたJSONの構造を確認し、stateの更新を setParts(data.items) に変更しました。JSXで表示する前に、オブジェクト、プロパティ、配列のインデックス、各要素のプロパティという順にレスポンスをたどり、データの参照パスを確認しました。

学んだこと: APIリクエストが成功しても、返ってきたデータがコンポーネントの想定どおりの形とは限りません。Reactのstateを更新する前にレスポンスの構造を確認し、画面に必要な値だけを保存することが大切です。

2026-08-21 · PartsPilot v2 · Docker / React / FastAPI / CORS / デバッグ / フルスタック

DockerのポートマッピングとCORSをデバッグする

コンテナ内部のポートとホストに公開されたポートを区別し、バックエンドのCORS設定を修正して、ReactからFastAPIへの接続エラーを解決しました。

詳細を見る詳細を閉じる：DockerのポートマッピングとCORSをデバッグする

問題: ReactのフロントエンドからFastAPIのバックエンドのパーツを読み込めませんでした。DockerはAPIをホストのポート8001で公開していたのに、リクエストは localhost:8000 に送られていました。また、ブラウザからのリクエストには、フロントエンドのオリジンからバックエンドのオリジンへアクセスするための許可も必要でした。

原因: Dockerのマッピング 8001:8000 では、FastAPIはコンテナ内のポート8000で待ち受け、ホストのブラウザからはポート8001を通してアクセスします。さらに、フロントエンドとバックエンドが異なるオリジンで動いていたため、ブラウザがCORSの制限を適用していました。

修正: フロントエンドのリクエストURLを http://localhost:8001/api/parts に変更し、FastAPIでフロントエンドの開発用オリジンからのリクエストを許可するよう設定しました。ブラウザのエラーとHTTPレスポンスの種類から、接続、ルート、認証、サーバー、CORSのどこで失敗しているのかを切り分けました。

学んだこと: Dockerのポートマッピングには、コンテナ側とホスト側があります。ブラウザで動くフロントエンドのコードはホスト側のポートを使う必要があります。また、クロスオリジンの許可はフロントエンドで回避するのではなく、バックエンドで設定するものです。

2026-08-04 · PartsPilot v2 · バックエンド / FastAPI / Pytest / SQLAlchemy / PostgreSQL / Docker

Docker外でPartsPilotのテストを動かす

分離したテスト用データベースとFastAPIの依存関係オーバーライドを導入し、Docker専用のPostgreSQLホスト名からテスト環境を切り離しました。

詳細を見る詳細を閉じる：Docker外でPartsPilotのテストを動かす

問題: ホストマシンから直接バックエンドのテストを実行すると、アプリケーションがホスト名 db でPostgreSQLに接続しようとして失敗しました。

原因: db はDocker Composeのサービス名でした。Composeネットワーク上のコンテナからは名前解決できますが、Mac上で直接実行するpytestのプロセスにとっては、有効なPostgreSQLのホスト名ではありませんでした。

修正: テストでは分離したSQLiteデータベースを使うように設定し、テスト実行中はアプリケーションのデータベース依存関係をオーバーライドしました。これにより、開発用のPostgreSQLコンテナに接続したりそのデータを変更したりせずに、エンドポイントのテストを独立して実行できるようになりました。

学んだこと: アプリケーションとテストの環境は、表に見えないインフラの前提を共有するべきではありません。依存性注入を使えば、開発と本番ではPostgreSQLを使い続けながら、管理されたデータベースに対してFastAPIのルートをテストできます。

2026-08-21 · PartsPilot v2 · Frontend / React / JavaScript / FastAPI / Debugging / Full-Stack

Fixing React API Response-Shape Rendering

Fixed a React rendering failure caused by storing an API response wrapper object in state instead of the parts array contained inside it.

Show detailsHide details: Fixing React API Response-Shape Rendering

Problem: The PartsPilot frontend successfully received data from the backend, but the interface failed when it attempted to run parts.map(). React expected parts to be an array, but the state contained the complete response object.

Cause: The FastAPI endpoint returned an object containing an items property rather than returning an array directly. The frontend used setParts(data), which stored the wrapper object in state. Array methods such as map could not be used on that object.

2026-08-21 · PartsPilot v2 · Docker / React / FastAPI / CORS / Debugging / Full-Stack

Debugging Docker Port Mapping and CORS

Diagnosed a failed React-to-FastAPI connection by separating the container’s internal port from the port exposed to the host and then correcting the backend CORS configuration.

Show detailsHide details: Debugging Docker Port Mapping and CORS

Problem: The React frontend could not load parts from the FastAPI backend. Requests targeted localhost:8000 even though Docker exposed the API to the host on port 8001. Browser requests also required permission to cross from the frontend origin to the backend origin.

Cause: The Docker mapping 8001:8000 meant FastAPI listened on port 8000 inside its container but was accessed through port 8001 from the host browser. The frontend and backend also ran on different origins, so the browser applied CORS restrictions.

Fix: Changed the frontend request URL to use http://localhost:8001/api/parts and configured FastAPI to allow requests from the frontend development origin. Used the browser error and HTTP response type to distinguish connection, route, authentication, server, and CORS failures.

Lesson: Docker port mappings have a container side and a host side. Browser-based frontend code must use the host port, while cross-origin permission must be configured by the backend rather than bypassed in the frontend.
